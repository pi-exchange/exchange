# Exchange

Высоконагруженная криптовалютная биржа: спотовые ордера, собственный matching-движок, балансы с эмуляцией ввода и вывода средств. Учебный проект по дисциплине «Программная инженерия», выполняется в течение семестра по лабораторным работам.

Подробное описание, структура, карта функций и план — в [docs/00-project.md](docs/00-project.md).

## Запуск

### Предварительные требования

- Git;
- Docker с Compose v2 (Docker Desktop или Docker Engine) — единственное, что нужно для запуска;
- для проверки: bash и curl (Linux, macOS, Git Bash) либо Windows PowerShell 5.1+.

Порт `8080` должен быть свободен. Чтобы сменить порт или параметры БД, скопируйте `.env.example` в `.env` и отредактируйте.

### Команды

```bash
git clone https://github.com/pi-exchange/exchange.git
cd exchange
docker compose up -d --build
./scripts/smoke.sh                                        # bash
# либо в Windows PowerShell:
powershell -ExecutionPolicy Bypass -File scripts\smoke.ps1
```

Первая сборка скачивает образы и занимает несколько минут. Остановка: `docker compose down` (с флагом `-v` удаляется и том с данными БД).

### Проверка работоспособности

Скрипт `scripts/smoke.sh` (`smoke.ps1`) выполняет три шага и завершается кодом 0 при успехе. Те же шаги можно сделать вручную:

1. `GET http://localhost:8080/health` → `{"status":"ok","database":"up"}`: сервис запущен, миграции применены, БД доступна.
2. `GET http://localhost:8080/api/v1/markets` → два рынка, `BTC/USDT` и `ETH/USDT`.
3. `GET http://localhost:8080/api/v1/markets/BTC/USDT/orderbook` → `{"market":"BTC/USDT","bids":[],"asks":[]}`: стакан по рынку (на чистой БД пустой; ордера появятся в ЛР4).

## Правила ведения репозитория

- Каждая лабораторная работа выполняется в ветке `lab-N` и попадает в `main` через pull request. Прямые коммиты в `main` запрещены.
- После слияния на итоговый коммит ставится тег `lab-N`.
- Замечания оформляются как issues с метками `review`, `bug`, `change-request`, `question`.
